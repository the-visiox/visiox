# VisioX — MinIO Storage Structure

## Overview

VisioX uses **MinIO** (self-hosted S3-compatible object storage) to store all media files, model weights, and temporary data.

MinIO endpoint: `http://10.29.30.20:9000`  
Console: `http://10.29.30.20:9001`

---

## Bucket Structure

| Bucket | Purpose | Lifecycle |
| --- | --- | --- |
| `visiox-media` | Dataset images/videos, augmented images | Permanent |
| `visiox-artifacts` | Model weights, training artifacts | Permanent |
| `visiox-tmp` | Upload staging, temporary export downloads | **Auto-deleted after 7 days** |

---

## Bucket: `visiox-media`

Stores all media files for datasets.

### `visiox-media` Directory Structure

```text
visiox-media/
└── orgs/{team_id}_{team_slug}/
    └── projects/{project_id}_{project_slug}/
        └── datasets/{dataset_id}_{dataset_slug}/
            └── v{version}/
                ├── raw/          <- original images/videos uploaded by user
                │   └── thumbs/   <- precomputed gallery thumbnails (~400px JPEG)
                ├── augmented/    <- images generated by augmentation (labels carried over)
                │   └── thumbs/   <- precomputed gallery thumbnails
                └── frames/       <- frames extracted from video
```

### Path Level Breakdown

| Level | Example | Meaning |
| --- | --- | --- |
| `orgs/` | `orgs/1_visiox-demo-lab/` | Organisation / Team. The number before `_` is the DB primary key |
| `projects/` | `projects/1_warehouse-qc-line-a/` | Project belonging to that team |
| `datasets/` | `datasets/1_factory-floor-v1/` | Dataset belonging to the project |
| `v{version}/` | `v1/`, `v2/` | Dataset version (incremented when creating a new version) |
| `raw/` | `raw/IMG_1000.jpg` | Original uploaded file |
| `augmented/` | `augmented/aug_1_IMG_1000.jpg` | File generated by augmentation (annotations + label profile carried over) |
| `*/thumbs/` | `raw/thumbs/IMG_1000.jpg` | Precomputed gallery thumbnail (`media.thumbnail`), served for `?quality=thumb` |

### Slug Naming Rules

- Lowercase: `Factory Floor V1` → `factory-floor-v1`
- Special characters and spaces replaced with `-`
- Maximum 40 characters
- ID prefix ensures uniqueness even if the name changes

```python
# Slug generator (datasets/models.py)
def _slug(name: str) -> str:
    return re.sub(r'[^a-z0-9]+', '-', name.lower()).strip('-')[:40]
```

## Bucket: `visiox-artifacts`

Stores model weights and artifacts produced by training jobs.

### `visiox-artifacts` Directory Structure

```text
visiox-artifacts/
└── training-jobs/{job_id}/
    └── weights/
        └── {filename}.pt / {filename}.onnx / ...
```

### `visiox-artifacts` Example

```text
training-jobs/42/
  weights/
    best.pt
    last.pt

training-jobs/manual/     <- manually uploaded model (not from a training job)
  weights/
    exported_model.onnx
```

### Supported Formats

| Format | Extension |
| --- | --- |
| PyTorch | `.pt`, `.pth` |
| ONNX | `.onnx` |
| TensorRT | `.engine` |
| TFLite | `.tflite` |
| CoreML | `.mlmodel` |

---

## Bucket: `visiox-tmp`

Temporary files. **Auto-deleted after 7 days** via MinIO lifecycle policy.

### `visiox-tmp` Directory Structure

```text
visiox-tmp/
└── orgs/{team_id}_{team_slug}/
    ├── uploads/{session_id}/     <- staging area for large uploads
    └── exports/{export_id}/      <- COCO/YOLO/VOC zip files for user download
```

## Django Configuration

```env
# .env
USE_MINIO=True
MINIO_ENDPOINT=http://10.29.30.20:9000
MINIO_ACCESS_KEY=admin
MINIO_SECRET_KEY=StrongPassword123
MINIO_BUCKET=visiox-media        # default bucket for Media files
```

```python
# settings.py — when USE_MINIO=True
STORAGES = {
    'default': {
        'BACKEND': 'storages.backends.s3boto3.S3Boto3Storage',
    },
    ...
}
AWS_STORAGE_BUCKET_NAME = 'visiox-media'
AWS_S3_ENDPOINT_URL     = 'http://10.29.30.20:9000'
AWS_S3_ADDRESSING_STYLE = 'path'   # required for MinIO (path-style addressing)
```

`ModelRegistry.model_file` uses a dedicated storage backend pointing to `visiox-artifacts` — see [core/storage.py](core/storage.py).

## Management Commands

| Command | Purpose |
| --- | --- |
| `python manage.py migrate_to_minio` | Migrate files from local disk to MinIO |
| `python manage.py migrate_to_new_structure --dry-run` | Preview migration from `teams/` to `orgs/` structure |
| `python manage.py migrate_to_new_structure` | Run the structure migration |
| `python manage.py migrate_to_slug_paths --dry-run` | Preview rename to slug-based paths |
| `python manage.py migrate_to_slug_paths` | Run the slug-path rename |
